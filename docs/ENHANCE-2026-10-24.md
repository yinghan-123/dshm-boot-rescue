半身（`lib/rescue-client.js`）分头实现，一律以本文件为准；任何一方要改字段，先改这里。

## 2. 硬约束（不许破）

- 所有读写只在 `$DSH_HOME`（`DSH_HOME` → `DSHM_HOME`）内；profile 必须是 home 子目录。
- 写接口：同源 `POST` + `application/json` + 回环 `remoteAddress` + 回环 `Host` 头；
  `@deepseek-ai/*` 内置 bundle 一律**不可**停用/移除；不能停用自己。
- 整批 fail closed：一个非法 id 整单拒绝。
- 原子写：备份（`<file>.dshm-boot-rescue.bak`）→ 同目录临时文件 → rename → 提交前复核。
- 零依赖、零遥测、只用 node 内置模块；客户端脚本零依赖、无 import/require。
- 宿主侧所有逻辑 `try/catch`，任何错误只写诊断日志，绝不影响宿主启动、绝不进入 pending。
- 新增文件/目录：

```text
$DSH_HOME/dshm-boot-rescue-ledger.json          # B 台账
$DSH_HOME/dshm-boot-rescue-snapshots/           # F 快照目录
  <ts>-<reason>/rows.yml | profile-package.json | meta.json
```

## 4. 路由契约

前缀仍是 `/dshm-boot-rescue`。写接口一律 POST + JSON（`content-type: application/json`）。

| 方法 | 路径 | 请求体 | 响应 `ok:true` 的关键字段 |
| --- | --- | --- | --- |
| GET | `/health` | – | `{ok,version,webServer,loader,route,tapIndex,indexInject,channels,injections,mode}` |
| GET | `/state` | – | 见第 3 节 |
| GET | `/client.js` | – | 脚本本体 |
| GET | `/preview` | – | 自检页 |
| POST | `/disable` | `{"ids":["…"]}` | `{disabled[],already[],mode,rescueRows[],warning,level}` |
| POST | `/restore` | `{"ids":[]}`（空=全部救援项） | `{restored[],skipped[],mode}` |
| POST | `/disable-bundle` | `{"ids":["…"]}` | `{removed[],alreadyFailed[],mode:"bundles"}` |
| POST | `/restore-bundle` | `{"ids":[]}` | `{restored[],skipped[]}` |
| POST | `/safe-mode` | `{"confirm":true,"keep":["…"]}` | `{levels:{rows:[],bundles:[]},kept[],skipped[]}` |
| POST | `/snapshot` | `{"reason":"manual"}` | `{id,at,path}` |
| POST | `/rollback` | `{"id":"…"}`（可省=最新） | `{restoredFrom:{id,at},rowsBytes,bundlesRestored}` |
| POST | `/quarantine/restore` | `{"name":"<文件名>"}`（可省=唯一候选） | `{merged:[],skipped:[],backup:"…"}` |

错误一律 HTTP 状态码 + `{ok:false,error,code}`，`code` 取值沿用现有风格：
`self-protected` `protected-id` `not-actionable` `unknown-id` `read-only` `remote-mutation-disabled`
`non-loopback-host` `content-type` `cross-origin` `payload-too-large` `invalid-ids`
新增：`unknown-bundle` `bundle-protected` `nothing-to-do` `snapshot-not-found`
`quarantine-not-found` `quarantine-unmergeable` `merge-conflict`。

## 5. D 三级停用语义

- `level` 由客户端显式传或由宿主按可用性推断（`/disable` 保持旧行为：rows → patch 降级）。
- `/disable-bundle`：只接受 `entries[].bundleRemovable === true` 的 id；把对应项从
  `profiles/<p>/package.json` 的 `dsh.profile.bundles` 数组移除（保持其余项顺序、不动
  `dependencies`、不改 `removeBundles`）。台账记 `mode:"bundles"`、`extra:{index}`。
- `/restore-bundle`：只把台账里记录过的 bundles 项**按原 index 插回**（index 越界就 append）。
- 保护名单：名字以 `@deepseek-ai/` 开头的一律不可移除；`dshm-boot-rescue` 自身不可移除；
  剥离后数组不允许为空，且必须仍包含 `@deepseek-ai/dsh-base` 与 `@deepseek-ai/dsh-web-app`
  （缺一个就整单拒绝，`bundle-protected`）。
- 空 `keep` 的安全模式行为见第 6 节。

## 6. F 安全模式与快照

- `/safe-mode`：目标 = `entries` 里 `actionable && !builtin && !protected && id != self`
  且 **不在** `keep` 里的全部 id。
  - 先把能走 rows 的写进用户行（一次批量）；
  - 对 `bundleRemovable` 且仍有风险的再走 bundles 移除（同一批 id 不重复处理）；
  - 返回两级各自移除的 id，`skipped` 记录没处理的（只读、patch 降级、不可映射等）。
  - 要求 `confirm:true`，否则 400 `nothing-to-do`（防止误触）。
- 快照目录 `$DSH_HOME/dshm-boot-rescue-snapshots/<YYYYMMDD-HHMMSS>-<reason>/`：
  - `rows.yml`（用户行文件原样，可能为空/不存在时写空文件并标 `exists:false`）
  - `profile-package.json`（profile 的 package.json 原样）
  - `meta.json`（`{id,at,reason,homeDir,profileDir,rowsPath,bundles[],version}`）
  - `keep` 默认 5 份，超出删最旧。
- 自动快照：`apply()` 成功后延迟 **15s** 存一份 `reason:"startup"`（宿主能起来就是好消息）；
  客户端检测到健康 UI 后再 `POST /snapshot {reason:"healthy"}`（30s 内去重，不重复写）。
- `/rollback`：备份当前 rows → 用快照 `rows.yml` 覆盖；`profile-package.json` 存在时
  只恢复 `dsh.profile.bundles` 数组（不动 dependencies）；返回被恢复的 bundle 数。全程原子写。

## 7. B 台账语义

- 文件 `$DSH_HOME/dshm-boot-rescue-ledger.json`，`{version:1, entries:[…]}`；
  `mode`/`level` 二选一（都写，同值）。
- `blockDigest` = `sha256` of 归一化行块：
  `[[id, disabled 值]]` → `id + "\u0000" + normalizedDisabled`（`true`/`false`/原文 trim）。
  **不含标记注释**，因此注释被 DSHM 抹掉后仍能匹配。
- 写入台账：`/disable`、`/disable-bundle`、`/safe-mode` 成功后 upsert（同 id+mode 覆盖 `at`）。
- 恢复优先级：① 注释标记块（现有逻辑）→ ② 台账 + `blockDigest` 匹配 → ③ 台账存在但块被改
  或找不到 → 拒绝并给出手改指引（`skipped` 里带原因）。
- 删除行块成功后，从台账移除该条（并写回文件）。
- 台账读不出来（损坏/非法 JSON）→ `ledger.ok=false`，功能降级为「只用注释标记」，
  不阻塞其它救援能力。

## 8. E 残留恢复语义

- 检测面：`$DSH_HOME/.dshm-boot-failed`（只读存在性 + mtime）、profile 目录里
  `*.quarantine-*`、`*.dshm-quarantine-*`、`*rows*.bak-*`（只读 + 解析统计）。
- `/quarantine/restore`：
  1. 目标文件固定为当前 `rowsPath`（`.dshm-plugin-rows.yml`）；
  2. 解析隔离文件的 `- id:` 块；当前文件里**没有**该 id 的才合并，已有则跳过（`skipped` 带原因
     `already-exists`），`disabled` 值不同的也跳过（`conflict`）；
  3. 合并时保留隔离文件里的救援标记注释（让恢复后的行仍可被救援中心识别与撤销）；
  4. 写入前备份当前文件（`.dshm-boot-rescue.bak`），原子写；
  5. 任何解析失败 → 整单拒绝 `quarantine-unmergeable`，不做部分合并。

## 9. C 客户端行为契约（rescue-client.js）

1. **失败页判定**= 满足全部：无健康 UI 信号（现有 `HEALTHY_UI_SELECTOR`）；根节点文本非空；
   且命中「失败信号」之一：
   - 现有标题 `Failed to load plugins` / 已知正则（保留）；
   - 新增宽松信号：`did not activate`、`import failed`、`client-modules`、`pending (`、
     `Failed to load`、`web boot:`、`waiting for service`、`cannot activate`、`loader entry`。
2. **兜底入口**（覆盖「文案完全变了」）：DOMContentLoaded 后 **15s** 若仍无健康 UI、也未挂载
   救援面板，则挂一个**右下角小胶囊**（不是全屏面板，不遮挡），点击才展开救援中心。
   小胶囊必须有：`role="button"`、`aria-label`、可键盘 ESC 关闭；健康 UI 出现即移除并停止。
   - 只要健康 UI 出现过（任何时刻），**永不**显示小胶囊。
   - 自检页（`data-dshm-boot-rescue-preview`）不显示小胶囊。
3. 面板新增区块/按钮（只在 `state.features.*` 为 true 且 `writable` 时可用）：
   - 「安全模式」按钮（二次点击确认，显示将停用的数量）；
   - 每行条目在 `levels` 含 `bundles` 时显示「bundle 停用」次级按钮；
   - 「隔离残留」区块：`quarantine.files` 列表 + 每项「合并恢复」；
   - 「快照」区块：`snapshot.latest` 时间/原因 + 「回滚到该快照」（二次确认）+「立即存快照」；
   - 「台账」区块：`ledger.entries` 数量 + 最近 5 条（id/time/mode）。
4. 所有写操作成功后**不重载页面**，只刷新 UI 并强调「划掉后台重新打开应用」。
5. 弹窗：新增结果的标题沿用 `已停用 N 个插件` 风格；安全模式额外一行「已进入安全模式」；
   回滚/合并成功提示需要重开应用。
6. 只读（`writable:false` 或自检页）时所有写按钮禁用并显示原因，不得发送写请求。
